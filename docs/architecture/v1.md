# P5EMU Architecture v1

**Architecture reference.** Originally written as a Phase 0 artefact defining
component boundaries; Phase 1 has since implemented the CPU core (decoder, IR,
validator, reference interpreter, differential harness). The boundaries below are
unchanged; the acceptance criteria in §8 record both Phase 0 and Phase 1 status.

---

## 1. Principles

These are ordered. When two conflict, the earlier one wins.

| # | Principle | Consequence |
|---|---|---|
| 1 | **The portable core must not depend on Xcode, and must not touch a platform API it cannot abstract.** | `core/` has no `mmap`, no `/proc`, no signals, no platform headers. The interpreter must be sufficient on its own for the iOS App Store tier |
| 2 | **The interpreter is the specification, not a fallback.** | It is always built, on every platform, in every configuration. It is the differential oracle |
| 3 | **No exceptions across a component boundary.** | Components return `Status`. The interpreter/JIT boundary is unwind-free |
| 4 | **Unknown is a valid state.** | Unimplemented returns `kUnimplementedInstruction`. Never guess |
| 5 | **No game-specific or title-specific hacks.** | Fixes address underlying emulation behaviour (adopted from shadPS4's `AGENTS.md`) |
| 6 | **Facts and designs are separable from code.** | Facts may be learned and re-typed. No third-party line is copied |
| 7 | **Differential testing is the only correctness argument.** | Every backend is checked against the reference, mechanically |
| 8 | **Platform differences are components, not `#ifdef`s.** | Windows/Linux/Apple are separate translation units behind interfaces |
| 9 | **A partially-correct component is worse than an absent one.** | No fake GPU, no speculative syscalls, no stub that silently succeeds |
| 10 | **Human review of AI-generated code is mandatory and recorded.** | Adopted from RPCS3's "AI Use" policy |

## 2. Layer model

```
   ┌──────────────────────────────────────────────────────────┐
   │  apps/ios/          app shell: Metal, touch, lifecycle   │  ← not in Phase 0
   ├──────────────────────────────────────────────────────────┤
   │  frontend/cli/      developer tools, headless runs        │
   ├──────────────────────────────────────────────────────────┤
   │  core/              PORTABLE. no platform headers.        │
   │    cpu/  loader/  memory/  kernel/  hle/                 │
   │    gpu/  audio/  input/                                 │
   ├──────────────────────────────────────────────────────────┤
   │  platform/          windows/ linux/ apple/                │  ← host OS only
   │    memory/  code_cache/  threads/  time/  fs/  log/      │
   └──────────────────────────────────────────────────────────┘
```

The boundary is **one-way**: `core/` never includes anything from `platform/` or
`apps/`. This is enforceable mechanically and must be, because it is the property
that makes the iOS tier possible.

## 3. Component boundaries

### 3.1 `core/cpu/decoder/`

Pure translation from guest bytes to `DecodedInstruction`.

- Portable C++, table-driven
- **No host feature detection.** A decoder that branches on host CPU features is
  a decoder that can disagree between builds
- Returns `kUnimplementedInstruction` for unknown encodings. Never guesses
- Owned entirely by P5EMU. See [`licenses.md`](../research/licenses.md) for why
  neither FEX's tables nor any GPL table is a source

### 3.2 `core/cpu/ir/`

SSA IR plus the pass pipeline.

- Explicit CPU-state ops (`LoadContext`/`StoreContext`) separate from memory ops
  (`LoadMem`/`StoreMem`). **The most important single design idea adopted**
- Sized, typed values (1/2/4/8 bytes; arbitrary vector element counts)
- Flags as first-class values, with an elimination pass
- Arena-allocated, referenced by `uint32_t` offset rather than pointer, so the IR
  is relocatable and cache-dense, and AOT-serialisable later
- **Register allocation expressed as IR ops** (`AllocateGPR`, `AllocateGPRAfter`,
  `AllocateFPR`, `SpillRegister`, `FillRegister`), not as a backend concern

### 3.3 `core/cpu/interpreter/`

The reference backend.

- Portable C++, no assembly, no host assumptions
- **Correctness over speed.** Obvious code beats fast code here
- Always compiled in. This is the App Store tier, not a debug mode

### 3.4 `core/cpu/arm64/`

The performance backend.

- **Not built on a non-AArch64 host.** It is a Phase 2 deliverable
- Routes memory through `GuestMemoryPort` unless `IdentityMapped()`
- Uses a `CodeCachePort` obtained from `platform/apple/`
- **Emits arm64e with PAC-signed pointers when targeting iOS** (Apple's
  documented requirement)
- Write-protect toggled **once per block entry/exit**, never per instruction

### 3.5 `core/memory/`

Guest address space.

- Guest VA == host VA **where the platform allows it** — it gives cache-coherent
  GPU access with no flush protocol
- Separate CPU and GPU protection axes (`PROT_CPU_*` / `PROT_GPU_*`)
- Process-lifetime reservation, so GPU page faults are recoverable
- **Demand-paged on iOS.** The PS5's 512 GiB extended region is not reservable
  in the App Store sandbox; this is the largest memory-design divergence and it
  is planned, not discovered later

### 3.6 `core/loader/`

Executable loading.

- ELF64 for the FreeBSD-derived Sony dialect. The tag namespace is **facts**, not
  code — see [`ps5-subsystems.md`](../research/ps5-subsystems.md) §1
- P5EMU's own implementation. `provenance` records that the constants were
  derived from public specification

### 3.7 `core/kernel/`, `core/hle/`

Kernel services and the host-library surface.

- **Symbol-database HLE**, not a syscall gate: `LIB_VERSION`/`LIB_FUNC`
  registration, per-symbol version resolution
- Rationale: a console's guest↔host traffic is overwhelmingly *library calls*,
  not syscalls, and versioned module resolution is the real problem
- iOS constraint: HLE surfaces stay behind P5EMU's own types. App Store guideline
  **4.7.2** restricts exposing native platform APIs to guest software

### 3.8 `core/gpu/`

Three strictly separated sub-layers:

| Sub-layer | Contains | Must never contain |
|---|---|---|
| `guest/` | Command processor, register state, resource model | Any host API type |
| `shader/` | RDNA2 decode → CFG → IR → backend | Any host API type |
| `host/` | Vulkan / Metal backends behind one interface | Guest state |

The rule in the third column is what keeps the shader compiler testable on a
headless CI box. A Vulkan handle appearing in `core/gpu/shader/` breaks it.

### 3.9 `platform/`

Host OS. Three implementations of the same interfaces.

| Interface | Windows | Linux | Apple |
|---|---|---|---|
| `MemoryPort` | `VirtualAlloc2` placeholders | `memfd_create` + `MAP_FIXED` | `shm_open` (no `memfd_create`) |
| `CodeCachePort` | `VirtualAlloc` + `PAGE_EXECUTE_*` | dual-mapping split-W^X | **`MAP_JIT` + `pthread_jit_write_protect_np`** |
| `ThreadPort` | `CreateThread` | `pthread_create` | `pthread_create` |
| `TimePort` | `QueryPerformanceCounter` | `clock_gettime` | `mach_absolute_time` |
| `LogPort` | OutputDebugString | stderr | `os_log` |

The Apple `MemoryPort` cannot use `memfd_create` (unavailable on Darwin). It
therefore cannot blindly copy any existing design; it is written from the
platform's own primitives.

### Deviations from the suggested structure, and why

| Suggested | Actual | Reason |
|---|---|---|
| `platform/common/` | `platform/{windows,linux,apple}/` + shared interfaces in `platform/include/` | There is no useful common layer. The *interfaces* are common; the implementations are not |
| `apps/ios/` with real content | `apps/ios/README.md` only | iOS work is Phase 4+. An Xcode project in Phase 0 would make the portable core untestable on CI and imply support that does not exist |
| `tests/{cpu,loader,memory,gpu}/` as directories | Flat test files in `tests/` with suite-prefixed names | Subdirectories earn their keep when a suite has ≥3 files. Adding structure now is speculative |
| `frontend/cli/` | Same | — |
| Separate `docs/research/` | Same | — |

Added, not in the suggestion:

- `scripts/check_provenance.sh` — mechanical provenance gate
- `tests/TestHarness.h` — because vendoring GoogleTest for three test cases
  would put a copyleft-adjacent dependency in the tree on day one
- `LICENSE.md` — the licence. Phase 0 held the decision open; it is now settled
  as proprietary/all-rights-reserved, with the constraints that shaped it
  documented

## 5. Dependency policy

**Zero third-party dependencies. Zero network access at configure time.**

The build must work air-gapped. This is a deliberate constraint: it keeps the
dependency surface auditable from day one, and it means CI cannot be broken by
an upstream release.

Planned dependencies, with the licence that governs each, are listed in
[`licenses.md`](../research/licenses.md). Each import is a legal event that gets
a `THIRD_PARTY_LICENSES/` entry and a `PROVENANCE.md` record.

## 7. Deliberate non-decisions

Recorded so they are not re-litigated every week.

| Not decided | Why | Revisit when |
|---|---|---|
| Custom IR vs LLVM IR | LLVM as a `core/` dependency makes the interpreter untestable without a toolchain. But LLVM is excellent for offline AOT | Phase 2, when the ARM64 backend needs a scheduler |
| "Splatter" codegen (no isel) vs instruction selection | Depends on the IR shape, which does not exist yet | After the IR has a hundred ops |
| Hand-written AArch64 encoder vs VIXL | Both viable; VIXL's A64 simulator is appealing for testing | Phase 2 spike |
| Native Metal backend | SPIR-V → SPIRV-Cross → MSL is sufficient for years | Phase 3 |
| Any GPU implementation | A fake GPU is worse than no GPU | Phase 2+ |
| Any `sceKernel*` implementation | Semantics are UNKNOWN | Phase 4+ |
